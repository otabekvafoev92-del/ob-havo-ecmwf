# Osmon · ECMWF 3D

3D-глобус с прогнозом ECMWF для всего мира. На нём объёмный рельеф с настоящими горами (для Центральной Азии — снимки Sentinel-2 и модель высот ~1,5 км), облака из модельного инфракрасного снимка ECMWF в несколько ярусов с тенями на земле, день и ночь по реальному положению Солнца, анимация дождя и снега. Есть границы стран и областей, контуры городов, прогноз по любой точке, сравнение двух точек, метеограммы ECMWF и оригинальные карты. Интерфейс на узбекском и русском. Каждые 12 часов данные обновляются сами, а сводка уходит в Telegram-бот.

**Погода** берётся только с **charts.ecmwf.int** (ECMWF OpenCharts, модель IFS): карты «Global» (весь мир, около 50 км) и «Western Asia» (Центральная Азия, около 11 км). Скрипт скачивает готовые карты и переводит цвета по их шкалам в значения.

**Облака** — продукт ECMWF «Simulated images – infrared» (`medium-simulated-ir`): серый снимок, где холодные (высокие) вершины облаков белые. Скрипт убирает с него линии границ и сетки и сравнивает каждый пиксель с тем, каким был бы безоблачный участок при прогнозной температуре 2 м; разница — плотность облака. Чем холоднее вершина, тем выше облако на глобусе (`pipeline/clouds.js`).

**Остальные данные** лежат готовыми в `site/assets/` и не меняются:
- рельеф: AWS Terrain Tiles (SRTM, GMTED, ETOPO), мир около 20 км, Центральная Азия около 1,5 км (`dem-ca.png`: высота = (R·256 + G)·4 − 1000 м);
- снимки: для Центральной Азии Sentinel-2 cloudless 2024 (`s2-ca.jpg`, © EOX IT Services GmbH, s2maps.eu, содержит изменённые данные Copernicus Sentinel; лицензия CC BY-NC-SA 4.0 — только некоммерческое использование), для мира NASA Blue Marble и Black Marble;
- границы, контуры городов и названия: Natural Earth (общественное достояние). Их можно пересобрать скриптом `tools/make_geo.py`.

## Как это устроено

```
pipeline/decode.js     расшифровка карт: палитры, рамка, проекции; сетки 330×180 (Ц. Азия) и 720×360 (мир)
pipeline/clouds.js     облака из инфракрасного снимка ECMWF → site/data/clouds/*.jpg
pipeline/build.mjs     скачивает рельеф, температуру, осадки 6 ч, ветер, солнце, облака, метеограммы, карты → site/data
pipeline/telegram.mjs  отправляет сводку и метеограмму Ташкента в Telegram
site/                  статический сайт (three.js, 3D-глобус), читает site/data/forecast.json и site/assets/
.github/workflows/update.yml  запуск в 09:20 и 21:20 UTC + публикация на GitHub Pages
```

Привязка карт к координатам: полярная стереографическая проекция, центральный меридиан 69,36° в.д. Параметры подобраны по маске моря с карты рельефа ECMWF, совпадение 95,9 % пикселей. Проверено по Баку, Иссык-Кулю, Балхашу и Алматы.

## Запуск на GitHub (бесплатно)

1. Создайте репозиторий на GitHub и загрузите в него все файлы этой папки.
2. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
3. Для Telegram (необязательно) откройте **Settings → Secrets and variables → Actions** и добавьте:
   - секрет `TELEGRAM_BOT_TOKEN` — токен от @BotFather;
   - секрет `TELEGRAM_CHAT_ID` — id чата, группы или канала (бота нужно добавить туда администратором);
   - переменную `SITE_URL` — адрес сайта, например `https://<логин>.github.io/<репозиторий>/`;
   - переменную `TG_LANG` — `uz` или `ru`;
   - переменную `TG_CITIES` — список городов через запятую, например `toshkent,samarqand,buxoro`.
   - переменную `PROB_TG` — какие видео-отчёты слать в канал, например `UZ:uz,cis:ru,TR:tr` (страна:язык).
4. **Actions → Update ECMWF forecast → Run workflow.** Первый запуск идёт около 1–1,5 часа (скачивание ~3 ГБ моделей и рисование 108 видео), потом сайт появится по адресу `https://<логин>.github.io/<репозиторий>/`.

GitHub Pages бесплатен только для **публичных** репозиториев: для приватного нужен GitHub Pro, иначе сделайте репозиторий публичным (Settings → General → Danger Zone → Change visibility).

Узнать `TELEGRAM_CHAT_ID` можно так: напишите боту любое сообщение и откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates`, там будет `"chat":{"id":...}`.

## Точность

- Температура известна с шагом шкалы ECMWF 4 °C, поэтому показывается интервалом, например «+12…+16°».
- Осадки за 6 часов даны классами шкалы: 0,5 / 2 / 4 / 10 / 25 / 50 / 100 мм.
- Ветер на картах закрашен только от 10 м/с, поэтому показывается «сильный ветер». Полный ветер есть на метеограмме ENS.
- Облака восстановлены из модельного ИК-снимка: тонкие облака над очень холодной поверхностью (зимой, в Арктике, на Тибете) видны слабее, а ночью над выхоложенной землёй возможны ложные тонкие облака.
- Вне Центральной Азии погода показана с шагом 0,5° (около 50 км).
- Положение на карте точное примерно до 5–10 км.

Лицензия данных: погода © ECMWF, CC BY 4.0; снимок Sentinel-2 cloudless © EOX, CC BY-NC-SA 4.0. Сайт не связан с ECMWF и EOX.

## Отчёт «Yog‘in ehtimolligi» для СНГ и Турции (`prob/`), 15 дней

Вкладка сайта с видео по 12 картам (СНГ и Турция целиком + 11 стран) на узбекском, русском и турецком. Для каждой карты три видео:
- **осадки** — вероятность ≥ 0,2 мм за 6 часов (синим дождь, фиолетовым снег), серым облачность, линии — температура;
- **температура** воздуха на 2 м;
- **облачность** (общая, %).
Под видео — комментарии по каждому дню (эти же фразы есть внизу каждого кадра), кнопка «скачать анимацию», скорость 0,5×/1×/2×.

Шаг по времени: **3 часа на первые 6 дней** (столько дают 3-часовых данных ECMWF IFS ENS и HRES, GEFS, GFS и ICON), дальше — 6 часов. AIFS (ансамбль и одиночная модель) выдаёт данные только раз в 6 часов, поэтому в 3-часовых периодах его нет, и это видно в списке моделей. Час в час данные дают только детерминированные модели и только на 2–4 дня, поэтому почасовой вероятности нет.

Как считается:
- `prob/fetch.py` скачивает только поле осадков (byte-range) из ECMWF IFS ENS, ECMWF AIFS ENS, ECMWF IFS, ECMWF AIFS (ECMWF open data, копия в Google Cloud, запасная — AWS), NOAA GEFS и GFS (AWS), DWD ICON; плюс среднее ансамбля GEFS для температуры и облаков (`wx.npz`).
- Вероятность — равный вес каждой системе: три ансамбля и группа детерминированных моделей.
- `prob/render.py` рисует кадры и MP4, `prob/telegram_send.py` отправляет в Telegram.
- Запуск — в `.github/workflows/update.yml` дважды в сутки (~3 ГБ трафика на сервере GitHub, 40–60 минут).

### Слой «5D-прогноз» на 3D-глобусе
`prob/export_5d.py` упаковывает тот же 15-дневный мультимодельный прогноз в маленькие картинки (`site/prob/d5/`, ~9 МБ): в каждой вероятность осадков, температура и облачность за 6 часов. На глобусе (кнопка «5D-прогноз») это пять измерений сразу:
- долгота, широта;
- высота — вероятность осадков (поднимается «горами»);
- время — плавная анимация на 15 дней по шкале внизу;
- цвет — дождь (синий) или снег (фиолетовый) по температуре; сверху плывёт слой облаков.
Переключатели: «Осадки + облака», «Температура», «Облачность». Кнопка «🎬 Записать 5D-видео» записывает пролёт по 15 дням вместе с датой и подписями и сохраняет MP4 (или WebM, если браузер не умеет MP4).

## Telegram

**Рассылка** (из GitHub Actions после каждого обновления): для каждой пары «страна:язык» из переменной `PROB_TG` (например `UZ:uz,cis:ru,TR:tr`) приходит один пост-альбом из трёх видео — осадки, температура, облака (листаются пальцем) — с подписью «по дням» на ближайшие дни, а следом кнопки «3D-глобус» и «Полный отчёт» (если задана переменная `SITE_URL`).

**Бот по запросу** (`telegram/worker.js`, бесплатно на Cloudflare Workers): человек пишет боту `/start` → выбирает язык → страну → кнопки «Сегодня и завтра», «По дням», «Видео на 15 дней», «3D-глобус». Бот берёт данные с вашего сайта (`prob/manifest.json` и видео), базы данных не нужно.
1. dash.cloudflare.com → Workers → Create → вставьте `telegram/worker.js`.
2. Settings → Variables: `BOT_TOKEN` (секрет, от @BotFather), `SITE_URL` (адрес сайта на GitHub Pages).
3. Откройте в браузере `https://api.telegram.org/bot<BOT_TOKEN>/setWebhook?url=<адрес воркера>`.

## Ветер, Солнце и Луна, вода, здания (глобус)
- Ветер: `pipeline/wind.py` — ECMWF IFS (open data) u/v у земли, 850, 500 и 250 гПа, анимация частиц на этих высотах.
- Солнце и Луна — по астрономическим формулам; точки «в зените», восход/заход и фаза Луны для выбранного места.
- Здания — контуры OpenStreetMap (Overpass API) при сильном приближении; если сервис недоступен, рисуются условные кварталы внутри контура города.
